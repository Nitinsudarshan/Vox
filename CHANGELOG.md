# Vox — Changelog

## [0.13.2] - 2026-09-26

### The WASAPI Crash Root-Caused, and the Review Close-Out

**Type**: patch — the Windows access violation traced to cpal's process-wide device enumerator and fixed at its source, plus the vault, import, capture, meetings, calendar and extension defects found reviewing the branch (`native/src-tauri/src/capture/device.rs`, `native/src-tauri/src/vault/mod.rs`, `native/src-tauri/src/meetings/*`, `native/src-tauri/src/calendar/*`, `native/browser-extension/*`).

#### Fixes

- **cpal's device enumerator is created on a thread that never exits (`native/src-tauri/src/capture/device.rs`)**: cpal's WASAPI backend keeps one process-wide `IMMDeviceEnumerator`, created inside the COM apartment of whichever thread asks first, and uninitialises COM when that thread exits. Capture threads live for one session, so when a recording was the first thing to touch audio the enumerator was left in a dead apartment and the next thread to open a device crashed the process with `STATUS_ACCESS_VIOLATION`. Every surface now takes its host from `capture::device::host()`, which on Windows first has a process-lifetime thread create the enumerator. The 100 ms settle delay added for this crash is removed: its premise was wrong, since on the runner the earlier tests never opened a stream.
- **cpal 0.16, for its WASAPI format-query fix (`native/src-tauri/Cargo.toml`)**: every capture start queries the device's formats, and cpal 0.15.3's `IsFormatSupported` path mishandled the closest-match buffer the API allocates. The CI test step now runs uncaptured, so a native crash shows the last output before it.
- **Frontmatter splits at the closing `---` line (`native/src-tauri/src/vault/mod.rs`)**: a `---` inside a title, summary or URL used to drop a scribble, strip a voice note's metadata, or cost a card its status. Voice-note strings are written as JSON and old Debug-escaped values are still read, so Hindi raw transcripts and Windows audio paths round-trip intact.
- **Import cannot traverse out of its folder (`native/src-tauri/src/vault/mod.rs`)**: export attachment names are reduced to one plain file name, attachment extracts are cut by characters rather than bytes (which panicked on Hindi text), permanent trash delete removes the trashed file or capture directory, and a vault id arriving from the webview must be one plain path component.
- **Example snippets ship disabled (`native/src-tauri/src/settings/mod.rs`)**: "sign off" typed "Best regards, Alex" into everyone's dictation. Unedited old examples are retired once. An unreadable `settings.json` is kept aside and settings are saved atomically.
- **Exports are read in bounded passes, and attachments stay with their capture (`native/src-tauri/src/capture/web/importer/mod.rs`)**: the conversations JSON is read first, capped at 1 GiB, without buffering every attachment; then only the attachments the chosen conversation names. Inspection reads no attachments at all, and archive reading runs on the blocking pool. Attachments are staged and moved into the capture `save_capture` returns — they were written under a second, invented capture id with no metadata, so nothing listed or trashed them and each re-import leaked a copy.
- **A stranded stop is recovered, and a live transcript cannot be erased (`native/src-tauri/src/meetings/engine.rs`, `native/src-tauri/src/meetings/store.rs`)**: a meeting found `Transcribing` at launch is recovered like one found `Recording` — a quit during a stop's final decode left it "Transcribing…" forever with 0 s and no player. `stop()` keeps the meeting in a finalizing slot until its record is written, so deleting it, moving the vault or starting another recording in that window is refused rather than resurrecting or splitting it. Translating a transcript or generating a report is refused while the meeting is still recording or finishing; both used to save the copy they read before waiting minutes on a model, erasing every line transcribed meanwhile. `write_atomic`'s temp file is unique per write, not per process.
- **Series opt-outs survive a sync, and syncs run one at a time (`native/src-tauri/src/calendar/sync.rs`, `native/src-tauri/src/meetings/model.rs`)**: taking a recording out of its series, or deleting the series, is remembered in `Meeting::series_opted_out` — the next sync put it back within minutes. Syncs save onto the account list as it is when they finish, changing only the sync fields, so an account disconnected during a sync no longer comes back with its events, and a cache write that fails is a failed sync with its reason rather than a success over stale events.
- **A multi-day event is on every day it overlaps (`native/src-tauri/src/calendar/mod.rs`)**: end-exclusive and capped at 31 days, so a conference that began yesterday and a 23:00–01:00 call are both on today's agenda. Starting a meeting opens its devices without holding the recording lock — a slow Bluetooth open froze every status poll on the main thread.
- **Meeting settings merge into what is stored now (`native/src/components/settings/MeetingSettingsView.tsx`)**: the page-load copy reverted the microphone and reminder choices saved by the controls embedded in the same view. Report progress belongs to its meeting, so another meeting no longer shows it or cancels through it, and a report that finishes while a different meeting is open still clears. A reminder action that fails brings the card back with the reason, instead of vanishing and logging to the console.
- **Cloud "Test Model" sends a real prompt (`native/src-tauri/src/commands/models.rs`)**: the new `test_active_provider` command goes through the saved provider; the old one reported "Configuration verified" after only saving settings, whatever the key.
- **The extension injects the bundle the build emits (`native/src/webcapture/bundle.ts`)**: the background worker asked Chrome for `relay-extract.js` while the build writes `vox-extract.js`, so every capture failed with "Could not load file". Both now take the name from one constant. Stopping the capture bridge joins its accept thread — every settings save restarted the bridge, and the old listener still held the port when the new one bound, so it fell back to a random port the paired extension did not know.
- **Dictation survives VS Code titles and refused hotkeys (`native/src-tauri/src/hotkeys/mod.rs`)**: stripping VS Code's "●" dirty marker sliced a byte into a three-byte character and panicked during injection. A hotkey the OS refuses restores the previous bindings instead of leaving no dictation hotkey until restart, and `save_settings` no longer persists the refused value. The stuck-key stop knows every key name the recorder emits — arrows, navigation keys, numpad, punctuation, F13–F24 — where an unknown name had silently disabled it. The hotkey handler opens the microphone on its own thread rather than the window thread, which froze every window while a cold device opened.
- **Dictation, pill and scribble bugs from review (`native/src/components/capture/DictationPill.tsx`, `native/src-tauri/src/pipeline/mod.rs`)**: dictionary, snippet and correction edits save the settings they produced rather than the pre-edit copy; the Diagnostics vocabulary-priming switch and prompt are saved, not only shown; Settings › Dictation loads the real microphone list. A new recording clears the previous result's collapse timer and any pending hover-leave, so dictating within 2 s of "Text inserted" no longer hides a live recording. `stop_capture` ends every `TRANSCRIBING` with `SUCCESS` or `ERROR`. Enrichment and summaries re-read the Scribble after the model call and merge only derived fields, so edits made meanwhile are kept and a result for content that has since changed is dropped.
- **Entity keyword matching uses offsets in the original text (`native/src-tauri/src/entities/mod.rs`)**: offsets taken from a lowercased copy overran it after "İ" and panicked.

#### Security

- **One Vox per user (`native/src-tauri/src/lib.rs`)**: `tauri-plugin-single-instance`, registered first. A second launch ran startup recovery against the live instance's recording, marked it recovered and deleted its checkpoints; it now only brings the running window forward.
- **Sign-in is bounded, and answers only its callback (`native/src-tauri/src/oauth/flow.rs`)**: Google sign-in gives up after five minutes instead of waiting forever when the consent tab is closed, and ignores requests other than the callback instead of failing on the first one with a state mismatch.
- **A legacy API key cannot leak to a third party (`native/src-tauri/src/providers/mod.rs`)**: the single legacy key is never sent to a custom endpoint or to Ollama, and is adopted once by the hosted provider that was active. `is_loopback_url` parses the host, so `127.example.com` and `localhost:1@remote.host` no longer count as this machine, and Ollama auto-start uses the same check instead of substring matching.
- **Account deletion stops when cloud deletion fails (`native/src-tauri/src/commands/account.rs`)**: it changes nothing and the success message no longer claims cloud deletion, or vectors that do not exist. Tests never touch the real OS credential store — running the suite signed the developer out.
- **Captured text is rendered as untrusted (`native/src/components/shared/MarkdownView.tsx`)**: Mermaid never runs on captured text, whatever the fence or wording; remote images load only when the reader asks, where opening a capture used to fire every tracking pixel the page carried; and a code fence closes only on a backtick run at least as long as the one that opened it, so captured code cannot escape its block.
- **A capture header cannot be forged (`native/src-tauri/src/web_capture/normalize.rs`)**: the markdown header renders the sanitized author and traversal — a multi-line author meta could forge a Source line and an assistant turn — and header lines are capped while reading, before the token is checked. Re-normalizing no longer appends Vox's own notes a second time.

#### Improvements

- **Capture dedupe says what it actually does (`native/src/webcapture/merge.ts`)**: text dedupe compares only the previous paragraph, where a page-wide set keyed on a 200-character prefix dropped repeated choruses and similar openings. Within a turn only images and attachments are collapsed. The sample merger keeps two identical turns seen together ("continue" twice) and matches later copies by nearest offset. A site extractor's result is not replaced by the reveal pass's generic blocks, so GitHub files keep their code block and issues lose the duplicate page copy. Relative image and download targets resolve against the page.
- **A confirmed decision becomes current (`native/src-tauri/src/memory/decision.rs`)**: so it reaches context packs and retrieval. `ollama serve` and `reg query` run without a console window, and the tray's "Start Recording", which only showed the window, is gone.

## [0.13.1] - 2026-09-26

### `commands.rs` Splits by Surface, and Six Frontend Controls Start Calling Commands That Exist

**Type**: patch — the 4,000-line command module split into `commands/`, a CI gate that fails on a frontend call to a command the backend does not define, and the correctness fixes found underneath both (`native/src-tauri/src/commands/*`, `scripts/verify-invoke-contract.mjs`, `native/src/lib/errors.ts`).

#### Improvements

- **One module per surface (`native/src-tauri/src/commands`)**: `commands.rs` held 153 Tauri commands in one file. It is now `commands/` with a module each for capture, notes, vault, models, app, diagnostics, account, web_capture, knowledge and test_lab. What the modules share — `AppState`, `CommandError`, the capture-status events, `persist_settings`, `record_stt_diagnostics` — stays in `commands/mod.rs`, and every module is re-exported, so `commands::<name>` paths are unchanged, including the `generate_handler!` list in `lib.rs`. A pure move: no command changed, and the only edit is the `include_str!` paths to `VERSION` and `CHANGELOG.md`, one directory deeper.
- **The living specs match the code (`docs/architecture.md`, `docs/product.md`, `docs/requirements.md`, `docs/data-model.md`)**: architecture, product, requirements and data-model described removed code as present — the trigger engine, MCP stubs that "return success", a LanceDB index under `.Vox/lancedb`, a Kanban board viewer, voice chat, TTS settings. Each now says what exists, what was removed and by which decision, and what was never built. `docs/decisions.md` gains Decisions 71–75, and the three generated benchmark reports move from the repository root to `docs/benchmarks/`.
- **`api.md`, `roadmap.md` and `user-flows.md` rewritten against the tree (`docs/api.md`, `docs/roadmap.md`, `docs/user-flows.md`)**: capture modes are `voice_note` and `todo`; `stop_capture` runs the shared dictation pipeline, not trigger matching or voice chat; the `process_transcript`, `update_card_status` and trigger commands never existed or were removed. `roadmap.md` says speaker grouping, calendar sync and reminders ship, where it had said they were removed. `maybe_later.md` goes back to its original item numbers, which decision records cite.

#### Fixes

- **Six frontend controls called commands the backend never defined (`native/src/components/settings/*`, `scripts/verify-invoke-contract.mjs`)**: such calls compile, typecheck and pass unit tests that mock `invoke`, then fail silently in the app. "Copy Diagnostic Info" called `get_diagnostic_summary`, now a real command returning a configuration summary with no key, path or transcript in it. "Explore Vault Folder" called `open_vault_in_explorer`, now `open_vault_folder`. The model pull called `pull_ollama_model`, now a real command restricted to an Ollama on this machine. Checking for updates called `check_for_updates`; the command is `check_for_app_updates`. Trashing a scribble from the knowledge graph called `move_to_trash`; it now uses `delete_scribble`. `npm run verify:invoke` fails CI on an unknown command, an argument the command does not take, or a missing required argument.
- **Opening a window no longer downloads a speech model (`native/src-tauri/src/commands/models.rs`)**: the dictation pill called `ensure_stt_model_ready` on mount and Settings › Advanced on open, so with no model configured, launching Vox on a fresh install fetched `ggml-small` (~466 MB) and pinned it — contradicting the README's "nothing is fetched behind your back". The new read-only `get_dictation_model_status` is what both surfaces call; `ensure_stt_model_ready` is now only the pill's explicit Download.
- **Every frontend error is typed (`native/src/lib/errors.ts`)**: a Tauri command error is a plain `{ code, message }` object, so ten `err instanceof Error ? err.message : String(err)` sites showed users "[object Object]" — a failed speech-model download among them. `describeError(err, fallback)` handles all three shapes, every `catch (err: any)` is typed, and no `any` remains in the frontend. The Files page's drag-drop listener no longer leaks when the page unmounts before `listen` resolves, which had made returning to Files import each dropped file twice.
- **An input stream finishes closing before another opens (`native/src-tauri/src/capture/mod.rs`)**: the capture thread owned the cpal stream and dropped it on its own schedule after being told to stop, so a stream's teardown overlapped the next one being opened — in the app, two dictations in quick succession with keep-warm off. `ActiveStream` now joins its capture thread when dropped.
- **Enrichment stops slicing the original text at offsets from its lowercase copy (`native/src-tauri/src/enrichment/mod.rs`)**: `extract_deterministic_title` found title markers in `text.to_lowercase()` and sliced the original at that byte offset. Lowercasing can change a character's length — `İ` becomes two characters — so the slice landed in the wrong place ("eep the knowledge layer") or inside a character, which panics. Markers and fillers are matched against the original with ASCII case folding, which finds the same text without moving any offset.

## [0.13.0] - 2026-09-25

### Dictation Cleanup Becomes Opt-In, Keys Move to the Credential Store, and Windows Finally Builds in CI

**Type**: minor — the async runtime unblocked, provider keys out of `settings.json`, a Windows CI job that compiles everything behind `cfg(target_os = "windows")` for the first time, four dependency advisories patched, and the Relay→Vox rename finished in everything a user can see (`native/src-tauri/src/capture/dictation.rs`, `native/src-tauri/src/providers/secrets.rs`, `.github/workflows/ci.yml`, `.github/workflows/security.yml`).

#### Features

- **Windows is built and tested in CI (`.github/workflows/ci.yml`)**: a new `rust-windows` job runs `clippy -D warnings` and `cargo test` on `windows-latest`. Until now nothing behind `cfg(target_os = "windows")` — injection, focus tracking, the Win32 unsafe calls, the credential store — was compiled in CI at all. The frontend job also runs `npm run build:extension`, since nothing else bundled the capture extension.
- **Dependencies are audited on a schedule (`.github/workflows/security.yml`)**: `cargo-audit` and `npm audit` run weekly and whenever a lock file or manifest changes. Production npm dependencies must be clean at moderate and above.

#### Security

- **Provider API keys live in the OS credential store (`native/src-tauri/src/providers/secrets.rs`)**: they were plain text in `settings.json`. The webview only ever sees a placeholder, keys are migrated on the next save, and they stay in the file if no credential store exists.
- **A fresh install writes to app data, not the launch directory (`native/src-tauri/src/lib.rs`)**: release builds kept a fresh install's data wherever they were launched from — System32 or Program Files. Existing data folders are still found and never moved; `VOX_HOME` overrides.
- **The MCP action stubs are gone (`native/src-tauri/src/actions`)**: they reported success without doing anything, and logged transcripts. The Triggers settings tab, which nothing ever executed, is removed with them.
- **The capture bridge is bounded (`native/src-tauri/src/web_capture/bridge.rs`)**: at most 16 concurrent connections, and accepted sockets are forced back to blocking, which on Windows they inherit from the non-blocking listener.
- **Four advisories patched (`native/src-tauri/Cargo.toml`)**: lopdf 0.34 via pdf-extract 0.7 (RUSTSEC-2026-0187) let a deeply nested PDF overflow the stack and abort the app on import — pdf-extract 0.12 brings lopdf 0.42, and a regression test builds such a PDF. quick-xml 0.36 (RUSTSEC-2026-0194/0195), quadratic attribute checking and unbounded namespace allocation, both reachable from an imported DOCX, now 0.42. rustls 0.23.43 (RUSTSEC-2026-0285) now 0.23.45.

#### Fixes

- **AI cleanup is opt-in (`native/src-tauri/src/capture/dictation.rs`)**: an empty or unrecognised `cleanup_style` now means Raw and no model call. It previously meant Faithful, so every dictation paid up to 5 s and, with a cloud provider selected, was sent off the machine. The unused `text_transform` flag is gone; `cleanup_style` is the one control.
- **The async runtime is no longer blocked (`native/src-tauri/src/capture/dictation.rs`)**: injection, clipboard writes and the 15 s focus-return wait run on the blocking pool instead of sleeping on the async runtime, and the recorder's resample/VAD/WAV write moved there too.
- **The hotkey and pill paths share one pipeline (`native/src-tauri/src/capture/dictation.rs`)**: `transcribe → finish_text → clean_up`, with unit tests. This fixes the hotkey path typing and saving an empty note when normalisation removed everything, and the pill's `voice_note` result now carries its note id. Toggle-to-talk no longer restarts a session on OS auto-repeat of a held stop key.
- **DOCX import keeps its spaces (`native/src-tauri/src/import/docx.rs`)**: the reader is ported to quick-xml 0.42, which reports entity references as separate events, and fixes an existing bug on the way — trimming every text event glued words together across formatting runs, so "This is " + "bold" + " text" imported as "This isboldtext". Run tabs and breaks are kept; tab-stop definitions are not treated as text.
- **Every vault-backed store is repointed when the vault moves (`native/src-tauri/src/lib.rs`)**: moving the vault repointed only `VaultManager`. The meeting store, and the memory, relationship and entity stores — which load their index once at launch — kept reading and writing the vault Vox had started with, and the asset scope the meeting player uses was never granted for the new meetings folder. `AppState::repoint_vault` moves all of them together; the three index-backed stores gain `reopen(vault_dir)`; and a vault move is refused while a meeting is recording, so one meeting cannot be split across two vaults.
- **The dispatcher test stops opening a browser (`native/src-tauri/src/actions/dispatcher.rs`)**: the read-only dispatch test executed the real `open_url` handler, which launches the system browser and on the Windows runner left Edge running behind the job. The dispatcher gains `execute_with(registry, ...)` and the test uses an inert handler. Windows tests now run one at a time, which also keeps tests touching process-wide OS state — clipboard, foreground window, credential store — from interleaving.
- **Vox says Vox, not Relay (`native/src/webcapture/background.ts`, `native/src-tauri/src/enrichment/questions.rs`)**: the rename missed strings that reach the user — the extension's capture notifications ("Saved to Relay", "Relay is not reachable…"), the dictation window's title, capture-size and model error messages, the "Relay dictation" provenance label. The deterministic question generator also used "Relay" as its fallback subject, so a note naming no entity got questions about Relay's knowledge layer. Internal identifiers (`get_relay_profile`, `RelayProfile`, the `RELAY_` environment fallbacks) are left alone: renaming them changes no behaviour and would break compatibility.

## [0.12.0] - 2026-09-22

### The Dictation Test Lab

**Type**: minor — a streaming segmenter and shadow dictation pipeline, plus a benchmark engine and workbench that compares models and cleanup styles over live audio or a recorded WAV (`native/src-tauri/src/capture/benchmark.rs`, `native/src-tauri/src/capture/streaming.rs`, `native/src/components/tests/DictationTestLabPage.tsx`).

#### Features

- **A streaming segmenter and a shadow pipeline (`native/src-tauri/src/capture/streaming.rs`)**: `StreamingSegmenter` wraps `Segmenter` for continuous mono speech and tracks a session's segment lifecycle. `StreamingDictationPipeline` runs concurrent STT and Faithful worker channels as a shadow of the live path, behind the `dictation_streaming_shadow` setting, with streaming PCM sink hooks on `AudioRecorder`.
- **Cleanup eligibility is decided deterministically (`native/src-tauri/src/capture/rewrite.rs`)**: `evaluate_cleanup_eligibility` stops a Faithful cleanup firing on an incomplete clause, where a model asked to tidy half a sentence finishes it instead.
- **A benchmark engine over live audio and recorded WAVs (`native/src-tauri/src/capture/benchmark.rs`)**: model discovery, cleanup-style comparison, and RTF/WER/CER per run, with a `phase4_5_benchmark` binary for cold-versus-warm and short-window latency. Tauri commands expose run execution, history management, and Markdown/JSON report export.
- **The Test Lab workbench (`native/src/components/tests/DictationTestLabPage.tsx`)**: live recording or an imported audio file compared across models, with model and cleanup-style selection cards, real-time progress, diff views and report export, behind a new `tests` item in the sidebar and header.

#### Fixes

- **The Test Lab primes Whisper the way production does (`native/src-tauri/src/capture/benchmark.rs`)**: hotkey dictation passes `build_stt_prompt()` — dictionary words plus the custom initial prompt — into Whisper's decoding config, and the Test Lab did not, so its accuracy for domain terms measured a recognizer that had never seen the user's vocabulary. The same prompt is applied and surfaces in the run's recorded `initial_prompt`.
- **Run storage cannot reach outside the runs folder (`native/src-tauri/src/capture/benchmark.rs`)**: `test_id` is validated before a run file path is built, so load, delete and export are confined to it.
- **Imported WAVs decode through the shared reader (`native/src-tauri/src/capture/benchmark.rs`)**: honouring channel count and 8/24/32-bit PCM, instead of garbling stereo or yielding no samples. `cancel_dictation_test_recording` is called when the Test Lab unmounts mid-recording, so the recorder is released for hotkey dictation and meetings.
- **The benchmark reports what it measured (`native/src-tauri/src/capture/benchmark.rs`)**: the language is resolved like production dictation, the production cleanup style always runs rather than another style's latency being substituted when it is missing, crashed parallel model tasks are reported as failed results, and the shadow pipeline reports time-to-first-token as unmeasured (`None`) instead of a hardcoded 35 ms.

## [0.10.0] - 2026-09-21

### Whisper State Reuse, the ASR Shootout, and a Corpus That Turned Out to Be a Square Wave

**Type**: minor — one `WhisperState` kept beside the model instead of rebuilt per segment, backlog-driven profile switching, and a comparison harness whose first act was to invalidate the corpus every published accuracy number rested on (`native/src-tauri/src/capture/stt.rs`, `native/src-tauri/src/meetings/transcription.rs`, `scripts/shootout.py`, `scripts/audio_guard.py`). Recorded as D-045 through D-054.

#### Improvements

- **Whisper's state is built once, not per decode (`native/src-tauri/src/capture/stt.rs`)**: `SttEngine` built a fresh `WhisperState` for every decode, and whisper-rs allocates the KV caches and compute buffers there — ~330 MB for `ggml-small`, as `StreamingTranscriber`'s own doc comment has said all along. The slot now holds the state beside the model. Because one state is shared by dictation, meetings and imports, the engine always sets `no_context`: that is what a fresh state already did, and the alternative is one surface's decode priming another's.
- **The cost is now visible (`native/src-tauri/src/capture/stt.rs`)**: the engine's timer started at `whisper_full`, so state construction sat outside `decode_ms` and therefore outside every real-time factor the pipeline reports. `state_create_ms` carries it.
- **Beam width is traded before speech is (`native/src-tauri/src/meetings/transcription.rs`)**: `BacklogTracker` moves the worker to the cheaper decode profile when the queue reaches 8 and back at 2, against a queue that holds 64. The queue's only previous answer to a decoder falling behind was to refuse segments — speech lost outright, bought by a beam search the machine could not afford. A worse line is still a line.
- **The prompt is composed rather than overwritten (`native/src-tauri/src/meetings/transcription.rs`)**: the worker assembled its prompt and assigned it over the one `from_settings_defaulting` had just filled, so a prompt the user configured applied to dictation and was silently dropped by meetings. It now reads `<configured>. <vocabulary>. <what was just said>` — Whisper treats the end of `initial_prompt` as the most recent thing said, so a keyword list there asserts that the last utterance was a list of names, and whisper.cpp truncates a long prompt from the front.

#### Fixes

- **`detected_language` reports what was decoded, not what was asked for (`native/src-tauri/src/meetings/transcription.rs`)**: it was set from the requested language, which is `None` for the long-form meetings the field exists for. It now comes from `whisper_full_lang_id_from_state`, recorded next to the request rather than in place of it.
- **corpus-v1 is 89% to 99% clipped, and every accuracy number from it is void (`scripts/audio_guard.py`, `docs/benchmarks/TRANSCRIPTION_BENCHMARK_V1.md`)**: `miniaudio.decode` returns signed 16-bit integers by default and the generator treated them as floats in [-1.0, 1.0], so `max(-1.0, min(1.0, s))` clamped every non-zero sample to full scale before multiplying by 32767. The corpus is the sign of the waveform. Nothing objected, because the files are valid 16 kHz mono WAVs of the right duration that play as recognisable speech, and Whisper transcribed them at 15.17% WER — a number in that range reads as a model result. The published 15.17% WER and 8.03% CER now carry a banner saying what they measure. `audio_guard.py` does the conversion explicitly for every format miniaudio can return, refusing one it does not recognise rather than assuming floats, and the generator declines to write a case that fails the gate.
- **The benchmark binary was not running the production path (`native/src-tauri/src/bin/benchmark.rs`)**: it built `WhisperDecodingConfig::baseline()` — greedy, encoder clamp off — while a meeting builds `for_meetings`, beam search at 3 with the clamp on. The committed 3.029 RTF was therefore never comparable to production. Every knob is a flag, every flag is in the output's `RunStamp`, the defaults are production, and an unrecognised flag is an error rather than a default.

#### Features

- **The shootout matrix (`scripts/shootout.py`, `scripts/engines.json`)**: one evaluator over every engine, a configuration recorded on every row, the audio checked before the models, and a comparative taxonomy that only reaches SEGMENTATION, CONTEXT or INFERENCE_ENGINE when a peer row holds the other variables fixed. An engine that cannot run is reported with its remedy, never dropped. The matrix is ordered so consecutive rows differ in one thing: Whisper Small, Base and Large-v3-Turbo, whole-file against segmented, three context modes, and the same weights under CTranslate2.
- **`--audio-stats-only` (`native/src-tauri/src/bin/benchmark.rs`)**: a recording's RMS, peak, near-clipping share, voiced ratio and SNR estimate with no model loaded, built on `capture::AudioStats` rather than beside it, so "near clipping" means the same thing here, in the benchmark and in a live meeting's diagnostics.
- **Two experiments that need no new engine (`native/src-tauri/src/meetings/benchmark.rs`)**: `--segmentation whole-file` and `--context none|static|previous`, which ask whether Vox's segmenter helps and whether prompt conditioning earns its place. Production stays `Previous`.
- **Real and public speech benchmark suites (`docs/public-speech-benchmark.md`)**: the corpus and the suites that run against it, plus a recognizer migration audit and a transcript-persistence investigation.

#### Testing

- **28 Python tests, in CI and behind `npm run test:transcription`**: they need no model and no corpus. Two caught real bugs while being written — the classifier could not match `ggml-small.bin` against `small`, so the engine-versus-model experiment silently never fired.

## [0.8.0] - 2026-09-19

### The Speech Architecture, Stages 0–12: From an Audit to Full-Duplex Readiness

**Type**: minor — the speech stack traced rather than described, then rebuilt around one principle: what the decoder said is evidence, and everything Vox concludes from it is derived and says so (`native/src-tauri/src/meetings/{benchmark,telemetry,speech_state,canonical,provenance,endurance}.rs`, `native/src-tauri/src/capture/{glossary,vocabulary,speech_health}.rs`, `native/src-tauri/src/{tts,conversation}/`). Recorded as D-001 through D-043 in `docs/speech-decision-log.md`.

#### Features

- **Domain vocabulary priming and a multi-stage quality screen (`native/src-tauri/src/capture/vocabulary.rs`, `native/src-tauri/src/capture/speech_health.rs`)**: the user's own terms reach the decoder as a prompt, and a staged screen judges what comes back before it is kept.
- **A benchmark that drives the meeting path, not a clip (`native/src-tauri/src/meetings/benchmark.rs`)**: `capture::evaluation` scored dictation — one clip, the whole-buffer VAD, one decode — across 35 dictation-length clips, and a meeting is none of those things. The new harness drives the real `Segmenter`, the real `speech_health` screen, the real `text_normalize` and a bounded queue taking its depth from `transcription::MAX_QUEUED_SEGMENTS`, with a test asserting that depth so the harness cannot drift into measuring a pipeline that does not ship. Twelve conditions, each with a duration floor — 30 minutes for a meeting — and a case below its floor is reported `UnderLength` rather than scored, because a word error rate over ten words is noise with three decimal places.
- **Decode telemetry is kept instead of printed (`native/src-tauri/src/meetings/telemetry.rs`)**: the worker measured every phase of a segment's journey and printed it with `println!`. `diagnostics.jsonl` appends one line per decoded segment, so the thousandth costs what the first did and a crash keeps every line before it; `diagnostics.json` is the rollup, written once on stop through `write_atomic`. `CaptureHealth` and `TranscriptionHealth` answer separately, because they fail for different reasons and are fixed by different actions. Four things are deliberately not recorded — transcript text, audio, speaker attribution and confidence — and model *filenames* are kept, never paths, because a diagnostics file gets attached to a bug report and a path names a machine.
- **Turn detection becomes a subsystem with a name (`native/src-tauri/src/meetings/speech_state.rs`)**: whether someone has finished speaking is an acoustic question, and the segmenter was answering it as a side effect of deciding which samples to hand a decoder. `speech_state` owns the decision — Silence → PossibleSpeech → Speaking → ProbableEnd → Finalized, the thresholds, the adaptive noise floor and both hysteresis counters. An extraction, not a rewrite: the segmenter's seventeen existing tests pass untouched. No LLM decides that a sentence has ended — it is a control problem answered in milliseconds, and routing it through a model would stop the pipeline working when the model does.
- **An engine declares what it cannot do (`native/src-tauri/src/capture/recognizer.rs`)**: `SpeechRecognizer`, whose interesting half is `RecognizerCapabilities`. A uniform result type forces every engine to look like the weakest, or to pretend: Parakeet reports no per-decode no-speech probability, and a uniform interface would have it return 0.0 with Vox's hallucination screen then grading it on a number it never produced. Support is three-valued — Yes, No, Unknown — and Unknown is never usable. `RecognizerChoice` has no variant that can hold a credential, and a test asserts the serialized form has no key or token field.
- **A transcript records which pass produced it (`native/src-tauri/src/meetings/model.rs`)**: `Meeting.transcript` carries the pass, the engine, the model filename, the language actually pinned, the decode profile and when it finished. It replaces `Meeting::transcript_model`, which held a full filesystem path and which nothing ever read. `transcript.live.json` is written once before the first final pass and never overwritten, so "the new transcript is worse than the old one" is a comparison rather than a memory.
- **Raw ASR evidence is separated from the canonical transcript (`native/src-tauri/src/meetings/canonical.rs`)**: `transcript.json` had five writers — the live worker, re-transcription, the English pass, romanization and speaker detection — so "what did the model actually say" and "what does Vox believe this means" were the same bytes. The assembler is a pure function that borrows the raw segments and never modifies them, and a test pins exactly that. It joins a ceiling cut only when the previous span really was cut at the ceiling, the two are adjacent to within one frame, and it is the same channel and speaker; strips the repeat at the join, because Whisper conditions on its own output; and states the gaps, because a transcript that silently omits ninety seconds reads as a complete record of a meeting in which nobody spoke for ninety seconds.
- **A glossary correction is evidence (`native/src-tauri/src/capture/glossary.rs`)**: the glossary was a find-and-replace inside the text normalizer, rewriting any token within one edit of a term before the segment reached disk, with nothing recording what had changed or from what. Each correction is now recorded — what the decoder said, what it became, which term did it, and why — and applying them backwards reconstructs the decode exactly. **A near miss is never corrected to a person's name**: names are short, numerous and collide with ordinary words, and getting one wrong changes who a meeting says made a commitment. It is not a spell-checker, and the test says so: "banglore" is four edits from "Bengaluru", obvious to a human, and left exactly as the decoder said it.
- **A claim can name the audio behind it (`native/src-tauri/src/meetings/provenance.rs`)**: `Evidence` names the meeting, the canonical lines, the raw sequences underneath them and the seconds they span; `Attributed<T>` wraps any claim. `locate` will not guess — it returns nothing when it cannot find the quoted text and refuses to anchor on fewer than three words, because an approximate provenance does not merely fail to help, it reads exactly like a real one. `summary.json` records the transcript a report was written from, including how many segments of recorded speech were missing from it.
- **A speech interface with no provider (`native/src-tauri/src/tts`)**: the plan for this stage assumed a local TTS path existed to wrap, and it did not — `talkback/` and `tts/` were absent while Decisions 47–56 and `maybe_later.md` §§1–3 described them in detail. Decision 69 records the removal. `TextToSpeech` with declared capabilities and `NullTts` behind it is not a placeholder: "no voice is set up" is the state of every fresh install. `tts::phrases` splits a streaming answer into speakable phrases, so time to first audio is first phrase plus one synthesis rather than whole generation plus synthesis; `tts::queue::SpeechQueue` is bounded, single-consumer and cancellable through a shared token rather than a flag checked between utterances, which makes the longest thing the system ever says its worst case — exactly the case that matters.
- **Who may interrupt whom, decided before anything can speak (`native/src-tauri/src/conversation`)**: a state machine and an event model with no audio, no model, no network and no Tauri command. The microphone stays open while Vox speaks, which is the whole of what full duplex means and the one property that cannot be acquired afterwards. `Thinking` belongs to Vox, but speech during it returns the turn and abandons the answer in flight. Barge-in requires consecutive held speech, not a single frame: on a laptop with no headphones the microphone hears the speaker, and a first-frame detector interrupts Vox with Vox every time. Acoustic echo cancellation is the real fix and needs a playback reference Vox does not have, so the guard is labelled a mitigation and 120 ms is a field on `BargeInPolicy` rather than a constant.
- **Re-transcription reports its progress (`native/src/components/meetings/RetranscribeDialog.tsx`)**: real-time progress, with the controls disabled while it runs.

#### Fixes

- **Losing audio is now as loud as losing a transcript line (`native/src-tauri/src/meetings/capture.rs`)**: the audit found the pattern backwards — every transcript loss was counted, warned and persisted, and every audio loss was a `tracing::error!` nobody reads during a call. Audio is the one artifact nothing can regenerate. Three silent failures now speak on their own `meeting-recording-warning` event, during the meeting, which is the only point at which the user can change device or free disk: no audio being saved, a failed checkpoint write (warned once — a full disk fails every write), and a microphone that did not open, whose mirror had no warning and left the worse half silent.
- **The unbounded path in front of the bounded one (`native/src-tauri/src/meetings/capture.rs`)**: the mixer-to-pump channel was an unbounded `std_mpsc` and both device FIFOs were unbounded `VecDeque`s, so a pump stalled on a slow disk grew memory with nothing shedding and nothing reporting. The channel now holds ten seconds and the mixer sheds past that with `try_send`; each FIFO holds a minute and discards its oldest. Unbounded is not the safe option, it is the option whose failure is worst, and only one of the two can be counted — `audio_lost_seconds`.
- **A shed block marks the join it left (`native/src-tauri/src/meetings/capture.rs`)**: shedding handed the next block whatever flag the shed block happened to carry, and a FIFO overrun set nothing at all. `discontinuity` is what makes the engine flush the segmenter, so both losses let the speech either side of a hole be stitched into one span and decoded as a single sentence — warned about, counted, and then papered over in the transcript.
- **Scoring is linear in memory (`native/src-tauri/src/capture/evaluation.rs`)**: the benchmark reused `calculate_accuracy`, written for 35 dictation clips of a few seconds, for a corpus whose `LongMeeting` floor is thirty minutes; it aligns with a full Levenshtein matrix. The shortest case clearing that floor took 3.3 GB of peak RSS and 31 seconds, and a two-hour case is sixteen times both. Each cell now carries its own operation counts forward and only the previous row is kept: thirty minutes goes to 46 MB and 16 s, two hours runs at all, at 50 MB and 4.4 minutes. The error rates are unchanged.
- **Two bounds that were not bounds (`native/src-tauri/src/meetings/store.rs`)**: the transcript parse cache was capped by nothing, so browsing a vault held every transcript opened since launch — both ways in now go through one helper with a cap of four. And `find_gaps` counted from the first sequence number to the last, which hangs on a transcript that has been corrupted or hand-edited; it now walks the sequences that exist.

#### Testing

- **A two-hour meeting in seconds (`native/src-tauri/src/meetings/endurance.rs`)**: every reliability property the pipeline claims is a claim about time, none can fail in a five-minute demo, and nobody runs a test that takes two hours. The harness drives the production `Segmenter`, `CheckpointWriter` and `MeetingStore` over generated audio of arbitrary length. It found what the audit had flagged MEASURE FIRST: `append_segments` rewrites the whole transcript, so over 1,439 lines the first hundred cost 40 ms to persist and the last hundred 2,056 ms. Fixed halfway on purpose — caching the parsed transcript keyed by meeting and validated against mtime takes the last hundred to 1,458 ms, and the 29% says the remaining cost is serializing and writing, not parsing. Removing the rest means a vault format change; the ceiling (~3,000 lines) is written down rather than left to be re-derived.
- **The audit that opened the work (`docs/speech-architecture-audit.md`, `docs/speech-decision-log.md`)**: traced from the implementation rather than the prose, covering data flow, twelve failure modes, latency and accuracy bottlenecks anchored to named modules, and a target architecture classifying every proposed change KEEP / CHANGE / MEASURE FIRST / DEFER. What it found that the documentation did not say: transcript loss was loud and audio loss silent; the decode queue was bounded and the channel in front of it was not; `transcript.json` had five writers; per-segment telemetry was thorough and entirely ephemeral; and there was no TTS code at all behind eleven documented modules.

### The Vault Gets an Index, and the Graph Gets Three Views Worth Reading

**Type**: minor — a parse cache and PageRank behind the knowledge graph, Rings, Focus & Flow and the Decision Tree as view modes with meaning in their geometry, and a TODOs surface over the kanban model that nothing had ever written to (`native/src-tauri/src/vault/scribble_index.rs`, `native/src-tauri/src/vault/kanban.rs`, `native/src/components/knowledge/*`).

#### Features

- **Scribbles are cached and incrementally indexed (`native/src-tauri/src/vault/scribble_index.rs`)**: `get_knowledge_graph` called `list_scribbles()`, which `read_dir`'d the scribbles directory and re-parsed every Markdown file on every call — so opening the graph, changing a filter and saving a thought each paid the full cost of the vault, and every view built on the graph inherited it. The index is keyed by path and stamped with each file's mtime and size; a refresh stats the directory and re-reads only what moved. The built graph, PageRank included, is cached alongside and rebuilt only when a file actually changed, so switching filters costs a clone and a retain rather than a vault walk. Measured cold index of 500 scribbles: 34 ms for 518 nodes and 1,000 edges; warm re-read 6 ms.
- **PARA is stored, not inferred (`native/src-tauri/src/vault/para.rs`)**: `ParaBand` is an explicit field on `Scribble`, with a lenient deserializer so one mis-typed band costs its own value instead of failing the whole frontmatter document and dropping the scribble from the vault. Absent means uncategorised, which is a state the UI shows rather than one it guesses.
- **Rings: position means something (`native/src/components/knowledge/RingsView.tsx`)**: the graph had one view, a force layout whose positions mean nothing — where a node sits was decided by physics and a `Math.random` seed, so the same vault drew differently every time. Band assignment is a lookup, so a node can never drift into a ring that misdescribes it; relaxation then runs inside the band. Reproducible by construction — seeded RNG, fixed iteration count, no convergence exit, input sorted by id — so two runs produce bit-identical coordinates. Filtering dims and never moves: `layoutRings` has no filter parameter at all.
- **Depth, temperature and motion that stops (`native/src/components/knowledge/graph/ringsRenderer.ts`)**: each thing the view wants to say gets one channel. Nodes fill with a radial gradient and an outer glow scaled from PageRank, and a dimmed node does not glow, because a filtered-out node that still shines defeats the filter. Saturation drains and lightness moves with age — towards ash in dark mode and towards paper in light, since fading towards black on a white background would make the oldest notes the loudest thing on screen. Each band fills as a low-alpha annulus drawn as two arcs with opposite winding, not a stack of discs. Nodes ease outward over 600 ms and the loop then stops dead: no ambient drift, no idle physics, and `prefers-reduced-motion` paints the final frame.
- **Every edge draws the meaning Vox already stores (`native/src/components/knowledge/graph/graphRenderer.ts`)**: the renderer coloured on one `relationship === 'DERIVED_FROM'` boolean and drew everything else the same grey at the same width. Colour is now the relationship type, case-insensitively so snake_case and SCREAMING_CASE arrive at the same colour, with an unknown type taking neutral slate rather than an invented hue. Width is the stored confidence, clamped to a hairline, because an edge we barely believe is not the same as an edge that is not there. Dashes say whether the link exists at all: `source: "ai"` means enrichment proposed it from shared topics and nobody confirmed it.
- **Focus & Flow (`native/src/components/knowledge/graph/focusRenderer.ts`)**: one root, work branching outward, and a click that answers "how did I get here" by lighting the route from the root and dimming everything else, with nothing moving. Knowledge is not a tree and this does not pretend otherwise — forcing a tree drops a link and duplicating the node says there are two thoughts where there is one, so one parent is chosen to hang the node from (containment beats derivation beats topic similarity) and every other real link is drawn as a dashed cross-link. Direction comes from the stored relationship type: `DerivedFrom` and `BelongsTo` get arrowheads, `RELATED_TO` and `SAME_TOPIC` get none. The canvas carries fallback content — a labelled list of the tree's nodes, each a button — so it is navigable by keyboard and legible to a screen reader.
- **The Decision Tree, on the memory layer's supersession (`native/src-tauri/src/memory/decision.rs`)**: a lens over `MemoryType::Decision` rather than a parallel store, because a second store means two answers to "what was decided". The confidence ladder is derived from evidence and never asserted by a caller — Confirmed 0.98, Captured 0.90, Extracted 0.55, Inferred 0.15 — and Captured stops at 0.90 deliberately, because the top is reserved for a decision confirmed twice. Standing is recomputed from attached evidence on every read, so a hand-edited `confidence` cannot promote a guess into something that draws as solid. **A decision with no traceable source is never captured**: recording one as captured or extracted without both a source and the words it rests on is refused outright, not quietly downgraded. Superseded decisions are kept, struck through and linked to what replaced them.
- **A TODOs surface over the kanban model (`native/src-tauri/src/vault/kanban.rs`)**: `KanbanCard` had existed since early on with working save and list, and nothing but tests ever wrote one. Every added field is optional on read, asserted against a byte-for-byte copy of the old writer's output. The writer now escapes values: it interpolated raw strings into a quoted line, which was safe only while every value was developer-authored.
- **Todos by voice, and the action items already being extracted (`native/src/components/todos/TodosPage.tsx`)**: a `todo` capture mode on the existing path — the same recorder, STT, normalisation and user dictionary as every other spoken capture, with no second recording implementation. Every way it can fail is a distinct visible message and none of them creates a todo, because a blank todo is indistinguishable from a bug. `ContextActionItem` has been extracted from browser captures all along, written into `context.json` and never seen again; those items now become todos idempotently on (source, title). The audit corrected the brief's premise: three of the four promised feeds have no extraction at all, and labelling browser captures as meetings to satisfy the letter of the brief would have put a wrong provenance on every card, so they get their own `web_capture` kind.

#### Testing

Opening the call re-arms the reminder a minute later, because the meeting still is not being recorded.
- **The recording pill came with it (`native/src/components/meetings/MeetingRecordingOverlay.tsx`)**: a right-edge capsule while recording — status dot, elapsed time, and one mirrored waveform with the user above the centreline and the meeting below — with pause and stop opening inside it on hover. The window resizes rather than staying large, since a transparent region still swallows clicks.
- **A meeting opens by its name (`native/src/components/meetings/MeetingsPage.tsx`)**: an agenda row had grown three targets a few millimetres wide, none of them the obvious thing to press, all competing with the meeting's name for the click. The row is one target now and says only what decides whether to open it; everything else moved into a dialog with room for it — the date and duration, your answer to the invitation, the location, the notes, and the guest list as an actual list rather than "+14". The actions are there and labelled: Join, and Join and record, which opens the call and starts recording under the meeting's real name rather than the clock.
- **Light and dark for the desktop surfaces, and Vox's name on them (`native/src/components/meetings/MeetingReminderWindow.tsx`)**: the pill and the card were ported as a fixed dark surface, which was defensible when they were somebody else's windows — a dark capsule pinned over a light app all meeting reads as some other program. Both now paint from the same `--card`/`--foreground` tokens as the rest of the app and follow the switch live, with the class applied before the first paint. The 30-pixel shadow and backdrop blur are gone: on a transparent window there is nothing underneath to catch a shadow, so it composited onto the desktop as a grey smear. An always-on-top capsule with a red dot and a running timer is a shape several screen recorders share, so the pill carries the mark and the card the wordmark.
- **The developer panel shows what detection sees (`native/src/components/settings/DeveloperSettingsView.tsx`)**: a `detected` reminder is the only kind no calendar can vouch for, so when one never arrives there are two explanations that look identical from outside — no conferencing window is open, or detection is blind on this machine. `debug_detect_conferencing_windows` returns the raw sightings, rendered in place rather than in a dialog, because a modal would cover the very windows being counted. Each row carries the cleaned title, the raw one, and the provider with its confidence. Window titles are somebody else's text, so they are shown and never interpreted.

#### Fixes

- **Nothing fired, because nothing kept the cache fresh (`native/src-tauri/src/meetings/reminders/scheduler.rs`)**: the loop read the event cache and nothing refreshed it except opening the Meetings page, so a user who launched Vox and worked elsewhere all day was reminded from whatever schedule Vox had last time somebody looked — and on a fresh install, from nothing. The loop syncs the calendar itself every five minutes, gated on the attempt rather than the result so a failing sync does not become a request every thirty seconds, and runs its first check five seconds after launch instead of thirty. Every tick logs what it saw: without that line, "no reminder appeared" and "no meeting was due" look identical from outside.
- **Three gates kept a real call silent while a mock one worked (`native/src-tauri/src/meetings/reminders/mod.rs`)**: **the stored setting** — changing a default only reaches installs that never stored a value, and settings are serialized whole, so saving any unrelated preference had written `"remind_on_detection": false` into every file; one correction on load, marked so it never repeats and written back immediately. **The calendar vouching for calls it knows nothing about** — a detected call was suppressed if any event within an hour either way used the same provider, including one already finished or declined, which during a working day is always true. **A ninety-second window** — the unrecorded reminder lived between five and seven minutes after the scheduled start, so it existed only for somebody already at their desk with Vox already running through all of it; it now stays open for as long as the meeting does.
- **Google Meet was invisible (`native/src-tauri/src/meetings/reminders/detection.rs`)**: Meet writes an en dash in its window title and every pattern matched the ASCII hyphen, so "Meet – abc-defg-hij" identified as no provider at all — a live Meet call registered as an empty screen. Dashes are folded before matching and stripped in all three forms when cleaning a title. `remind_on_detection` also shipped defaulting to false, and `#[serde(default)]` resolved to false rather than to the struct's own default, so a settings file written before the field existed kept the old behaviour even after the change.
- **A Zoom call is seen by its window class (`native/src-tauri/src/meetings/reminders/detection.rs`)**: a process is the wrong unit on Windows, since Zoom and Teams both sit in the tray all day, so their presence says nothing about whether a call is up. Zoom's in-meeting windows have classes of their own that exist only during a call, and those are matched when the title does not. Teams and Webex have nothing comparable — Chromium and ATL shells whose classes every other app of the same build shares — so there is nothing there to match that would not also match a browser. The developer panel reports the verdict beside each sighting: which signal saw it, and, when it would raise nothing, which gate stopped it. Verified against the Windows target for the first time: `cargo check --target x86_64-pc-windows-msvc` now compiles the `cfg(windows)` detection code, which no gate in this repo had ever built.

## [0.4.0] - 2026-09-15

### Recurring Meetings Become a Series, and Vox Announces One Before It Starts

**Type**: minor — `recurringEventId` carried through sync into a real series object, a reminder engine built on buckets rather than alarms, and the agenda keeping today's finished meetings where they can still answer for themselves (`native/src-tauri/src/meetings/series.rs`, `native/src-tauri/src/meetings/reminder_service.rs`, `native/src-tauri/src/calendar/parse.rs`).

#### Features

- **A recurring meeting has an identity (`native/src-tauri/src/meetings/series.rs`)**: a weekly standup recorded for three months is twelve meetings with twelve near-identical names and nothing linking them, so "what has happened across this meeting" cannot be asked — there is no object that is the standup. The identity is Google's: every occurrence carries `recurringEventId` once `singleEvents=true` expands the rule, which the sync already asks for, and `parse.rs` was discarding it. Inferring a series from matching titles and times was rejected, because two teams both running a "Weekly Sync" at 10:00 would merge into one, silently, with no way for the user to see it happened. Membership is written onto the meeting during a sync and never cleared by one — deriving it on read would look right for a month and then lose its older occurrences, because the event cache is a rolling thirty-day window. A membership the user set by hand outranks the sync, which is what makes manual assignment the escape hatch for a series Google split by deleting and recreating the recurrence.
- **A series reads forwards (`native/src/components/meetings/MeetingSeriesView.tsx`)**: a meeting's banner names its series and says where it sits in it — "Weekly Sync 9/12" — and opens the whole series in place. The list reads oldest first, against the meetings list's own newest-first order, because a list of what happened lately reads backwards and a series reads forwards: "what did we decide in week one and what has changed since" starts at week one. "Add to series…" covers what the calendar cannot — imported audio has no event and never will — and the dialog reads its own list, because a stale one would assign a meeting to a series that no longer exists.
- **A meeting is announced before it starts (`native/src-tauri/src/meetings/reminder_service.rs`)**: Vox knew the schedule and said nothing about it, and a calendar you have to remember to look at does not remind you. The timing rule is buckets, not alarms: lead times — fifteen, ten, five, one minute, at the start — define which bucket an event is in at any moment, the tightest one it has already reached. That matters for the case the naive design breaks on. Vox closed at 09:45 and opened at 09:57, three minutes before a 10:00 call, with 15/5/0 configured: one alarm per lead is three notifications about one meeting, two of them wrong about how long is left. Buckets make it one, and the text is written from the clock, so it says three minutes. A bucket fires once — nothing re-notifies, snoozes or escalates, because a reminder that arrives twice is worse than one that arrives once. Never announced: all-day events, meetings more than five minutes under way, and anything declined unless asked for. A thirty-second poll rather than a timer per event, because a timer array has to be rebuilt on every sync, settings change and clock change, and the failure mode of getting that wrong is a reminder that silently never fires.
- **The card, and the timing settings behind it (`native/src/components/meetings/MeetingReminderCard.tsx`)**: a reminder appears at the app root rather than on the Meetings page, since one that only shows up on the page you were already looking at reminds nobody. Its countdown is recomputed from the clock rather than counted down from the value it arrived with, so a card that sits through a laptop sleeping shows the real time left, and the same meeting announced again at a closer lead time replaces its card instead of stacking. Settings gets the lead times as a fixed set of chips rather than a minutes box, with a note that picking several does not mean several notifications, and writes through its own command — a checkbox carrying the whole settings document back lets a stale copy overwrite whatever else changed meanwhile. Choosing no lead times says so, rather than silently never announcing anything.
- **Today's finished meetings stay, dimmed (`native/src/components/meetings/MeetingsAgenda.tsx`)**: the agenda deleted a meeting the moment it ended, which makes the question it exists to answer unanswerable — "did the 10:30 happen, and did I record it?" is asked at 11, and the row that answers it had just disappeared. Dimmed rather than struck through, since the strike-through already means "you declined this" and the two states are unrelated. They keep their join link, because a call that breaks and resumes uses the same one. Days before today are cut instead of dimmed, and the section is "Your day" now, because "Coming up" stopped being true of it.
- **The OAuth callback page is Vox's (`native/src-tauri/src/oauth/page.rs`)**: branded, with a light and dark logo, rather than the default page a user is returned to after consenting.

#### Security

- **An ampersand can no longer smuggle the tag that follows it (`native/src-tauri/src/calendar/parse.rs`)**: `flatten_html` scanned for the closing `;` of an entity without caring what it passed on the way, so a `<` inside that ten-character window was flushed verbatim along with everything after it — `&<img src=x onerror=alert(1)>` came back out of the flattener with its tag intact, the one input that made the flattener not flatten. An entity name is letters, digits and `#`, so the scan stops at the first character that cannot be one, and `&;` is no longer treated as an entity. Not exploitable as things stand, since the only consumer renders the description as a React text child, but it is a hole in a boundary `rules/untrusted-input.md` says is absolute. The existing test asserted the invariant on an input that never exercised the gap; four smuggling shapes are covered now, and a second test pins the ampersands that must survive as themselves — "Tom & Jerry" and "R&D" still read as they were typed.

## [0.2.0] - 2026-09-13

### Multilingual Meetings: Script Variants, Translation, and a Decoder That Can Afford Them

**Type**: minor — romanization made a projection rather than a model call, English sourced from a second Whisper pass, acoustic speaker grouping, multi-account calendar, and a decode profile that moves with the script actually coming back (`native/src-tauri/src/meetings/transcription.rs`, `native/src-tauri/src/capture/romanize.rs`, `native/src-tauri/src/meetings/speakers.rs`).

#### Features

- **Original, Romanized and English, as three real renderings (`native/src-tauri/src/meetings/commands.rs`, `native/src/components/meetings/MeetingTranscript.tsx`)**: romanization and translation were one model call asking for both fields, and a local model answered both with the same string — the two views were byte-identical. Romanization is now a projection: `capture::romanize`, offline, faithful by construction, no model. `variants::accept_translation` refuses a "translation" that is merely the romanization back again. English comes first from a second Whisper pass in translate mode, which reads the audio rather than a transcript that may already be wrong, and the model pass fills what it missed in validated batches, reporting failure instead of saving the transcript unchanged. Reports are built from the English rendering. The toggle is hidden for English meetings, and the same romanization is wired through dictation and voice notes.
- **Speakers, presented as a proposal (`native/src-tauri/src/meetings/speakers.rs`)**: MFCC statistics per turn, clustered, with a span of audio per group so a voice can be heard and named. Presented as a proposal because that is what acoustic grouping can honestly claim. The microphone channel is never split and the two channels never merge, so a remote voice cannot be attributed to the person running Vox. Named speakers reach the summarizer, which is what lets a report attribute anything on a call of more than two.
- **Several Google accounts, merged into one day (`native/src-tauri/src/calendar/mod.rs`)**: read-only. Work and personal do not merge on their own and "what am I doing today" is the union of them; an invitation in both inboxes appears once, and recordings are matched to events by overlap rather than by nearest start.
- **Segment telemetry and deterministic recovery in the worker (`native/src-tauri/src/meetings/transcription.rs`)**: what each segment cost, and a recovery path that does not depend on the order failures happen in.

#### Improvements

- **A non-Latin transcript is decoded with a cheaper profile (`native/src-tauri/src/capture/stt.rs`)**: a Hindi meeting on `ggml-small.bin` ran at pipeline RTF 1.255 where an English one on the same model and settings ran at 0.319, and none of the earlier work touched it because all of it was aimed at the encoder and this cost is in the decoder. Whisper's tokenizer is fitted to Latin text: Devanagari spends several tokens where English spends one, the decoder runs once per token, and a beam search multiplies every one of those steps by three. With the encoder-window effect removed, decode time tracks transcript length at r = +0.80 in Hindi and r = −0.17 in English, and the same model spent 18.3 ms per character of English against 103.8 ms per character of Hindi. `for_expensive_script` drops to `SttPreset::Fast` and zeroes `temperature_inc`, reusing the preset rather than hand-assembling it because the beam and the no-speech threshold belong together. Which profile a segment gets is decided by what the decoder has already written, not by the user's language settings: a bilingual profile says what someone might speak, not what this meeting is. This is a real trade — greedy decoding and no fallback are less accurate, on exactly the audio whose accuracy is already weakest — and both traces name which profile ran, so the accuracy side can be judged against the same recording.
- **And it can move back (`native/src-tauri/src/meetings/transcription.rs`)**: the switch above was one-way, which was wrong for a meeting that runs in English, turns to Hindi for a few minutes and goes back — the English tail stayed on the cheaper profile for the rest of the recording, and the fast profile also raises `no_speech_thold` from 0.4 to 0.6, so a quiet speaker in that tail is likelier to be dropped from the transcript entirely. That is content loss, not a quality wobble. `ScriptTracker` moves on a run instead: two consecutive segments in an expensive script to drop the beam search, three consecutive Latin ones to take it back. Consecutive is load-bearing, since agreement resets the run, so genuinely code-switched speech stays where it is. The asymmetry is deliberate and compile-time asserted — returning is the accuracy win but also the throughput risk. The summary prints the whole path a meeting took ("careful → fast @seq 4 → careful @seq 11"), because a single switch point could not describe a meeting that changed language and changed back.
- **Re-transcription is a dialog, and a batch run has no clock (`native/src-tauri/src/meetings/import.rs`)**: `BatchConfig` now carries one decode profile instead of two, so re-transcribing Hindi structurally cannot decode more cheaply than English — a batch run reads a file already on disk and has nothing to keep up with. `for_meeting_batch` drops the encoder clamp and defaults to Quality. Nobody presses re-transcribe when the transcript is fine, and repeating the settings that produced a wrong one produces it again, so it asks. Language can now be pinned, because Whisper re-detects every thirty seconds and a chunk decoded under the wrong language comes back as fluent nonsense rather than as an error.
- **The meetings index is one column, and a meeting gets the whole window (`native/src/components/meetings/MeetingsPage.tsx`)**: grouped by day, with secondary actions moved into an overflow menu, instead of the right-hand half of a split.

#### Fixes

- **Reports stay in one language (`native/src-tauri/src/meetings/summary/processor.rs`)**: the summarizer prefers the translated text and the report is held to a single language, rather than mixing the two renderings in one document.
